# issue-09: コース一覧・課題一覧ページ

## 概要・背景・目的

学習者がコースを選び、課題を選ぶための一覧画面を構築する。
コース一覧ではアンロック状態とゴール提示 (Level 1: 完成版をプレイ可能) を表示し、
課題一覧では進捗状況と各課題のゴール提示 (Level 2) を表示する。

ロック中のゲームも「遊ぶ」ことはできる設計とする。
ロックされているのは「作る権利」であり「見る・遊ぶ権利」ではない。

## 受け入れ条件

- [ ] apps/web/src/app/(main)/courses/page.tsx にコース一覧ページが存在する
- [ ] 各コースのアンロック状態が表示される
- [ ] アンロック済みコースからは課題一覧へ遷移できる
- [ ] ロック中のコースも「遊ぶ」ボタンからプレイ画面へ遷移できる
- [ ] apps/web/src/app/(main)/courses/[slug]/page.tsx にコース詳細 (課題一覧) ページが存在する
- [ ] 各課題の進捗状態 (未着手 / 挑戦中 / クリア) が表示される
- [ ] apps/web/src/app/(main)/play/[slug]/page.tsx にゲームプレイ画面が存在する
- [ ] ゲームプレイ画面では、コースの模範実装 (リファレンスビルド) が動作する
- [ ] レスポンシブ対応: スマホでもコース一覧・課題一覧が快適に閲覧できる
- [ ] `make verify` がエラーを発生させない

## 技術的な検討事項

- コース一覧の並び順は courses.orderIndex に従う
- アンロック判定のロジックは core/learning/course-service.ts に置く。初期は「最初の簡単なゲーム課題をクリアしたら複数コースが一気にアンロック」というシンプルなルール
- プレイ画面は courses.playableBuildPath を参照して模範実装をロードする。ビルド済み成果物の配信は Supabase Storage または public/ ディレクトリ。MVP では public/ で十分
- コース一覧ページには並走者のランキング情報も表示する想定だが、それは issue-10 で実装する
