# issue-11: ログインボーナス・デイリーガチャ

## 概要・背景・目的

yutori の報酬設計の基盤を構築する。
ログインボーナスとデイリーガチャにより「開くと良いことがありそう」という
獲得期待を生む。損失回避 (開かないと損をする) は用いない。

連続ログインが途切れてもペナルティはなく、小目標が再設定されるだけとする。

## 受け入れ条件

- [ ] ログイン時にログインボーナスの付与判定が行われる (core/reward/bonus-service.ts)
- [ ] 1日1回のデイリーガチャが引ける
- [ ] 水曜・土曜に確率アップが適用される
- [ ] ガチャ結果としてコインまたは Cosmetic アイテムが得られる
- [ ] 課題スキップアイテムがガチャの低確率枠に含まれる
  - 所持中は再出現しない
  - 使用後は3ヶ月間の出現制限
- [ ] ガチャ確率の動的調整 (裏設定) が実装されている
  - ログイン頻度が高い人: 確率をそっと上げる
  - ログインが久しぶりの人: 確率をそっと上げる
- [ ] 連続ログイン (ストリーク) が profiles で管理される
  - 途切れてもペナルティなし
- [ ] ボーナス受領履歴が daily_bonuses テーブルに記録される
- [ ] ダッシュボードにログインボーナスとガチャの UI が表示される
- [ ] `make verify` がエラーを発生させない

## 技術的な検討事項

- ガチャ確率の動的調整幅は「気づかれない程度のそっとした恵み」に留める。具体的な数値は運用しながら調整する
- 課題スキップアイテムはストアの棚にも並べるが、通貨では購入できない。ストア UI はissue-13 で実装
- ガチャ・ボーナス関連テーブル (daily_bonuses の拡張、ガチャ履歴) がDB に追加で必要になる。この issue 内で Drizzle マイグレーションを行う
