# yutori

ゲーム制作で学ぶ、プログラミング学習サービス。

テトリスのようなゲームを、課題をひとつずつ解きながら少しずつ完成させていく。
学ぶことは本来楽しい。作ることは本来楽しい。
yutori は、その楽しさを邪魔しているノイズを取り除くことを設計の中心に置く。

---

## 名前について

「ゆとり」は、空間や時間に余白があることを指す言葉である。
焦らず、自分の好きな時間で、コツコツ学ぶ。その思想を名前に掲げている。
設計判断に迷ったときは「それは yutori な選択か」と問い直す。

---

## このサービスが目指すもの

過去にプログラミング学習で挫折した経験のある人を、取りこぼさないこと。
学習する気力が満ちている日は、思ったより少ない。
気力がある日にしか開けないサービスは、疲れている人を置き去りにする。

yutori は「勉強しに行く場所」ではなく「帰ってくる場所」を目指す。
気力がない日でも、なんとなく開ける。開けば、自分の整えた学習スペースがある。
その流れの中で、ふと「課題の続きをやってみようかな」と思う日がある。
思わない日があってもいい。それでも明日また帰ってこられる。

---

## 既存の学習サービスとの違い

既存のプログラミング学習サービスは、おおむね次のいずれかの文化を持つ。

- 競技プログラミング系: 厳格な値一致による採点。正解はひとつ。
- ステップ学習系: 答え合わせの文化。先に進むことが目的化しやすい。
- スキルチェック系: 評価が目的。学習過程への伴走は薄い。

yutori は「優しい厳しさで、仕様思考を育てる」というポジションを取る。

具体的には次の点で異なる。

- 課題はゲーム制作。最初の課題から、画面に動く成果物が現れる。
- 採点は値の一致ではなく仕様 (型・構造) への適合で判定する。
  出力に揺らぎがあっても、仕様に合致していれば合格とする。
- 失敗は罰ではなく対話として表現する。
  「ここまでは合っている」を必ず示し、ヒントは答えではなく問いかけで渡す。
- AI の使用を強制も推奨もしない。自己責任・自己管理に委ねる。
- 称賛機能を持たない。演出された称賛は信頼を壊すため、事実の提示に徹する。

## 設計を貫く二原則

すべての設計判断は、次の二原則から導かれている。

### 主体性をユーザーに返す

音はデフォルト OFF。アニメーションは OS 設定を尊重する。
ランキングは表示の ON/OFF を選べる。ヒントは答えを与えず問いかける。
どう使うか、どこまで助けを借りるかを、ユーザー自身が決める。

### 認識は丁寧に、正確に渡す

コントロールはユーザーに渡すが、フィードバックは惜しまない。
「いまどこまで来ているか」「ここは合っている」という認識を、漏らさず正確に届ける。

## 主な仕組み

### ゲームを少しずつ完成させる課題

各コースは、最終ゴール (完成版ゲーム) を先に提示してから始まる。
最初の課題で、薄くても端から端まで動く骨組みを完成させる。
以降の課題は、前の課題で作ったコードの上に積み上がっていく。

### 採点エンジン

ユーザーのコードは QuickJS-WASM のサンドボックス内で実行される。
採点は5つの観点 (構造・契約・基本・仕様・頑健) を上から順に確認し、
通過状況をリアルタイムに表示する。

### 草・並走者

学習の進捗はコントリビューショングラフとして可視化される。
ランキングは全体順位を見せず、進度の近い「並走者」だけを表示する。
追いつけずに諦める状況を、構造的に避けるための設計。

### ゆとりのある報酬設計

ログインボーナス、デイリーガチャ、不定期に出現する期間限定課題。
これらは「開かないと損をする」恐怖ではなく「開くと良いことがありそう」
という期待で人を引き寄せる。報酬は学習内容に一切影響しない。

## 技術スタック

| 領域 | 採用技術 |
|------|----------|
| フレームワーク | Next.js (App Router) |
| 言語 | TypeScript |
| スタイリング | Tailwind CSS + shadcn/ui |
| スキーマ / 仕様記述 | Zod |
| ORM | Drizzle |
| テスト | Vitest (単体) / Playwright (E2E) |
| Lint / Format | Biome |
| サンドボックス | QuickJS-WASM |
| ID 生成 | nanoID |
| ホスティング | Oracle Cloud A1 + Coolify (セルフホスト) |
| 入口 | Cloudflare + Cloudflare Tunnel |
| DB | PostgreSQL (A1 上) |
| 認証 | Keycloak + Auth.js |
| ストレージ | A1 + Cloudflare 配信 |

採点エンジンは Next.js に依存しない独立パッケージとして実装する。
将来の解析レイヤーには Go 1.24 WASM (リアクター) を検討している。
インフラは Oracle Cloud A1 上のセルフホスト構成。A1 はパブリック IP を持たず、
Cloudflare Tunnel 経由で公開する。構成の詳細は docs/a1-infra-reference.md を参照。

## リポジトリ構成

モノレポ構成を採る。

```
yutori/
├── apps/
│   └── web/            Next.js 本体
├── packages/
│   ├── grader/         採点エンジン (Next.js 非依存)
│   ├── sandbox/        QuickJS-WASM ラッパー (隔離実行層)
│   └── contracts/      共有 Zod スキーマ・型定義
├── content/            コース・課題の定義データ
├── tooling/            開発・運用スクリプト
└── docs/               設計ドキュメント
```

詳細は docs/directory-structure.md を参照。
